# Debian image backend

This backend wraps the NordOS composition in a Debian runtime package and installs it in a disposable guest. The base disk supplies the Linux kernel and bootloader. The Cutefish toolkit and login manager are separate inputs. The VM uses Debian repositories for the remaining runtime packages.

Use the Debian 13 `generic` amd64 QCOW2 image and compare it with the publisher's checksum. Record the base image version, checksum, component source revisions, and the three local packages and their checksums in the build manifest. The first build used base version `20261103-2651`, toolkit package `1.0~git20261111034643.6371e1b-1`, and login manager package `1.0~git20261028062042.77e1229-1`. [Debian Cloud images](https://wiki.debian.org/Cloud)

1. Build the selected components into a fresh stage using the [composition driver](../../README.md). Run `python3 distribution/image/debian/image.py dependencies --stage /path/to/stage > runtime-dependencies.txt` on the Debian build host. This uses `dpkg-shlibdeps` and the host's installed package metadata to produce the runtime dependency list.
2. Run `python3 distribution/image/debian/image.py package --help` for the package arguments. Pass the stage, the generated dependency list, the toolkit version, and each built component's `--source name=directory` to carry its licenses. The resulting `nordos-foundation` package owns the staged runtime files. Keep the toolkit and login manager packages alongside it.
3. Generate an Ed25519 key for provisioning and a private, randomly generated local login password. Write its `openssl passwd -6` hash to a private file. Run `python3 distribution/image/debian/image.py seed --help` for the seed arguments. Pass the three packages, the public key, the password hash, and the build manifest. Keep the seed ISO private. [NoCloud provisioning](https://docs.cloud-init.io/en/latest/reference/datasources/nocloud.html)
4. Copy the base disk with `qemu-img convert -O qcow2`, grow the copy to 32 GB with `qemu-img resize`, and boot it with the seed ISO attached as a CD-ROM. Allow network access so the guest can install Debian packages. If using SSH to administer the build, forward it to a host loopback port and connect using the build key. Wait for `/var/lib/nordos/image-ready` and check `/var/log/nordos-image-build.log`. The provisioning script switches the next boot to NetworkManager and enables the graphical login.
5. Shut down the guest, detach the CD-ROM, and cold boot it. Check the local Wayland session, the system services, NetworkManager, and the desktop tools. The package inventory and manifest are saved under `/var/lib/nordos/`.
6. Run `finalize.sh` as root in the freshly built guest. It removes provisioning access and powers the guest off. With the guest stopped, export a standalone image with `qemu-img convert -c -O qcow2` and run `qemu-img check` on the result. Boot a copy of that export to verify the delivered disk.

This records the inputs and the installed Debian package versions. Debian repositories can change between builds.
